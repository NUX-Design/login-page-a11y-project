# Login Page A11Y Practice Project

โปรเจกต์ฝึกใช้ `A11Y.md` ร่วมกับ AI เพื่อปรับปรุงหน้า Login ที่มีปัญหา Accessibility

## เป้าหมาย

นักเรียนจะได้ฝึกทำงานแบบสั้น ๆ 4 ขั้นตอน:

1. เปิดหน้า Login และลองใช้งานเหมือนผู้ใช้จริง
2. ให้ AI ตรวจปัญหาโดยอ่านกติกาจาก `A11Y.md`
3. ให้ AI แก้ไขโค้ด แล้วอธิบายว่าแก้อะไร
4. ตรวจซ้ำด้วย Keyboard, Zoom และ Screen Reader

## เริ่มใช้งาน

ไม่ต้องติดตั้ง Package ใด ๆ

1. Clone โปรเจกต์นี้
2. เปิดไฟล์ `index.html` ใน Browser หรือเปิดด้วย Live Server
3. อ่าน `A11Y.md` ก่อนเริ่มให้ AI ช่วย
4. ทดลองหน้า Login เดิม แล้วจดปัญหาที่พบใน `REPORT.md`

## Prompt สำหรับใช้กับ AI

คัดลอกข้อความนี้ไปใช้กับ AI ที่ทำงานในโฟลเดอร์โปรเจกต์:

```text
อ่าน A11Y.md ก่อนเริ่มงาน

ตรวจสอบหน้า Login ในโปรเจกต์นี้ตามกติกา A11Y.md โดยเน้น WCAG 2.2 ระดับ AA
อย่าแก้โค้ดทันที ให้รายงานปัญหาเป็นตารางก่อน โดยมีคอลัมน์:
- ปัญหา
- ผู้ใช้ที่ได้รับผลกระทบ
- ไฟล์และจุดที่พบ
- กฎ A11Y.md หรือหลัก WCAG ที่เกี่ยวข้อง
- วิธีแก้ที่แนะนำ

หลังจากฉันตรวจรายงานแล้ว ให้แก้โค้ดให้ใช้งานได้จริง และสรุปการเปลี่ยนแปลง
พร้อมบอกสิ่งที่ยังต้องตรวจด้วยคนจริง
```

## งานที่นักเรียนต้องส่ง

- หน้า Login หลังแก้ไขแล้ว
- `REPORT.md` ที่มี Before / After
- รายการทดสอบที่ทำจริง พร้อมผลลัพธ์
- ข้อจำกัดหรือสิ่งที่ยังไม่ได้ทดสอบ

## Definition of Done แบบเข้าใจง่าย

- กด `Tab` เดินผ่านทุกช่องและปุ่มได้ตามลำดับ
- เห็นตำแหน่ง Focus ได้ชัดเจน
- ทุกช่องกรอกมี Label ที่สัมพันธ์กับช่องนั้น
- ส่งฟอร์มโดยไม่กรอกข้อมูลแล้วรู้ว่าต้องแก้ตรงไหน
- ใช้ Zoom 200% แล้วยังอ่านและใช้งานได้
- ใช้ Screen Reader แล้วเข้าใจชื่อช่อง ปุ่ม และข้อความผิดพลาด
- ไม่อ้างว่า “ผ่าน Accessibility” หากยังไม่ได้ตรวจจริง

## โครงสร้างไฟล์

| ไฟล์ | ใช้ทำอะไร |
| --- | --- |
| `index.html` | หน้า Login ตั้งต้นที่ตั้งใจใส่ปัญหาไว้ |
| `styles.css` | รูปแบบ Before และพื้นที่ให้นักเรียนปรับปรุง |
| `script.js` | พฤติกรรมการส่งฟอร์มและข้อความสถานะ |
| `A11Y.md` | กติกาที่ให้ AI ใช้เป็นบริบทก่อนแก้โค้ด |
| `REPORT.md` | แบบฟอร์มบันทึกผลการตรวจของนักเรียน |

## ข้อควรจำ

เครื่องมือและ AI ช่วยค้นหาปัญหาได้ แต่การตรวจด้วย Keyboard และ Assistive Technology ยังต้องทำโดยคนจริง
